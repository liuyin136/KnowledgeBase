## 1. Prerequisites (Windows)

Install these on the Windows host BEFORE the first `docker compose build`:

1. **Docker Desktop** (latest stable) with the **WSL2 backend** enabled.
   - Verify in Docker Desktop → Settings → General → "Use the WSL 2 based engine" is checked.
   - Verify in Docker Desktop → Settings → Build → "BuildKit enabled" is checked (default in ≥ 4.34).

2. **NVIDIA Windows driver** (latest Game Ready or Studio driver).
   - Verify in PowerShell:
     ```powershell
     nvidia-smi
     ```
     Should print the GPU info (e.g. "NVIDIA GeForce GTX 3070 Ti, 8192 MiB").

3. **WSL2 Ubuntu distro** (for GPU passthrough).
   ```powershell
   wsl --install -d Ubuntu
   wsl --set-default-version 2
   ```
   - Verify: `wsl -l -v` shows Ubuntu with `VERSION` `2`.

4. **NVIDIA Container Toolkit** (installed INSIDE WSL2 — gives Docker access to the GPU).
   Inside WSL2 Ubuntu:
   ```bash
   # Run from the WSL2 Ubuntu shell (NOT PowerShell)
   distribution=$(. /etc/os-release;echo $ID$VERSION_ID)
   curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
   curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
     sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
     sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
   sudo apt-get update
   sudo apt-get install -y nvidia-container-toolkit
   sudo nvidia-ctk runtime configure --runtime=docker
   sudo systemctl restart docker
   ```
   - Verify the GPU is visible to a CUDA container:
     ```powershell
     docker run --rm --gpus all nvidia/cuda:13.3.0-devel-ubuntu26.04 nvidia-smi
     ```
     Should print the GPU info from inside the container.

> **Windows Server caveat**: Docker EE on Windows Server (without WSL2) does
> NOT support `--gpus all` natively. Use WSL2 Ubuntu distro or a Hyper-V
> Linux VM with PCI passthrough. Documented in `docker/README.md` §2.2.

## 2. One-Time Setup

Run these from the project root (the folder containing the root
`docker-compose.yml` thin wrapper):

```powershell
# ── 1. Copy the environment template ─────────────────────────────────────────
Copy-Item docker/.env.example .env
# Edit .env if you need to override defaults (e.g. set DOWNLOAD_BGE=1 to
# also pre-fetch the BGE alternative models so the Settings toggle is instant).

# ── 2. Build all 5 images (BuildKit is default in Docker Desktop ≥ 4.34) ──────
docker compose build
# First build: ~15-25 min (downloads Jina v5 small + Jina Reranker v3 + pip
# deps). Subsequent code-only builds: <60s (BuildKit HF + pip cache mounts).

# ── 3. Download models (Jina default; set DOWNLOAD_BGE=1 in .env first to
#       ALSO fetch BGE-M3 + BGE-reranker-base in this same run) ────────────────
docker compose run --rm backend python scripts/download_models.py
# Idempotent — re-running skips already-downloaded files.

# ── 4. Initialize the Neo4j schema (constraints + 1024-dim vector indexes
#       + fulltext indexes; idempotent — every statement uses IF NOT EXISTS) ──
docker compose run --rm backend python scripts/init_neo4j.py
# Prints a per-statement status table; exits 0 when all statements succeed.
```

## 3. Start / Stop / Logs

```powershell
# Start all 5 services (neo4j, redis, backend, api-worker, frontend) in the background.
docker compose up -d

# Check health + state of all services.
docker compose ps

# Tail logs (Ctrl+C to stop tailing; containers keep running).
docker compose logs -f backend
docker compose logs -f api-worker
docker compose logs -f neo4j
docker compose logs -f frontend

# Stop + remove containers (named volumes neo4j_data + redis_data are KEPT).
docker compose down

# Stop + remove containers AND drop named volumes (full reset — Neo4j data
# + Redis data are lost; re-run init_neo4j.py after `up -d`).
docker compose down -v
```

## 4. Service Endpoints

| Service | URL | Purpose |
|---|---|---|
| **Frontend (Next.js)** | http://localhost:3000 | The RAG Lab UI (Dashboard, Ingest, Search, Memory, Experiments, Settings) |
| **Backend (FastAPI)** | http://localhost:8000 | REST API + `/docs` (Swagger UI) |
| **Backend health** | http://localhost:8000/health | Healthcheck endpoint (used by Docker + the Next.js proxy) |
| **Neo4j Browser** | http://localhost:7474 | Graph DB admin UI (Cypher console) |
| **Neo4j Bolt** | bolt://localhost:7687 | Driver protocol (used by `neo4j-driver` in the backend + Next.js proxy) |
| **Redis** | localhost:6379 | Job queue (no UI; inspect via `docker compose exec redis redis-cli MONITOR`) |

> The Next.js frontend proxies all `/api/v1/*` requests server-side to
> `http://backend:8000`. Browser clients only ever talk to port 3000.

## 5. Neo4j Browser Usage

1. Open **http://localhost:7474** in a browser.
2. Connection URL: `bolt://localhost:7687`
3. Username: `neo4j`
4. Password: `P@ssw0rd` (from `.env` → `NEO4J_PASSWORD`; change in `.env` if
   you customised it, then `docker compose down -v && docker compose up -d`
   to reset).

### Useful Cypher queries

```cypher
-- 1. Five most recent experiments (any kind) with status + chunk counts.
MATCH (e:Experiment)
RETURN e.id, e.description, e.kind, e.status, e.total_chunks, e.created_at
ORDER BY e.created_at DESC
LIMIT 5;
```

```cypher
-- 2. Knowledge parents + their child chunks (ingest hierarchy).
MATCH (k:Knowledge)-[:HAS_CHUNK]->(c:KnowledgeChunk)
RETURN k.source_file, c.chunk_index, c.token_count, c.chunk_method, c.embedding_method
LIMIT 25;
```

```cypher
-- 3. Memories persisted from past searches (query + retrieved chunk text).
MATCH (m:Memory)-[:RETRIEVED]->(c:KnowledgeChunk)
RETURN m.query_text, c.text, m.final_score
LIMIT 10;
```

```cypher
-- 4. Vector search example (cosine similarity against a 1024-dim query vector).
--    Replace [0.1]*1024 with a real 1024-dim query vector from the backend.
--    NOTE: the Neo4j vector index is 1024-dim cosine (per neo4j-schema-v1.1.md §3).
--    Both Jina v5 (Matryoshka-truncated to 1024) and BGE-M3 (natively 1024)
--    write into the SAME indexes — no index re-creation needed when switching.
MATCH (c:KnowledgeChunk)
WITH c, vector.similarity.cosine(c.vector, [0.1]*1024) AS score
ORDER BY score DESC
LIMIT 5
RETURN c.chunk_index, c.text, score;
```

```cypher
-- 5. Verify vector + fulltext indexes exist (run after init_neo4j.py).
SHOW INDEXES;
-- Expect: chunk_vector_index (vector, 1024-dim, cosine) + chunk_text_fulltext (fulltext).
```

## 6. Running `.py` Files Inside the Running Container

The runtime image sets `PYTHONPATH=/app`, so `scripts/*.py` files can import
from `app.*` without any extra environment.

```powershell
# ── Re-run the Neo4j schema init without restarting the stack ─────────────────
docker compose exec backend python scripts/init_neo4j.py

# ── Re-download / refresh models inside the running container ─────────────────
docker compose exec backend python scripts/download_models.py
# (Set DOWNLOAD_BGE=1 in the container env first to also fetch BGE alternatives.)

# ── Run an arbitrary one-off Python snippet inside the backend container ──────
docker compose exec backend python -c "from app.core.config import settings; print(settings.embedding_repo, settings.model_dim)"
```

### Editing scripts on the host + seeing the change inside the container

The runtime image **bakes the backend code in** at build time (`COPY . ./`
in Stage 2 of `Dockerfile.backend`). Editing a script on the host does NOT
affect the running container — to test a script change:

```powershell
# Option A: rebuild the backend image (recommended for production-like testing).
docker compose build backend
docker compose up -d --force-recreate backend api-worker

# Option B: dev-only — mount the backend/ directory as a volume so edits
# are picked up live. Edit docker-compose.yml `backend` service:
#   volumes:
#     - ../backend:/app
# Then recreate the backend container:
docker compose up -d --force-recreate backend
# Now `docker compose exec backend python scripts/...` runs the edited script.
# Remember to remove this volume mount before deploying to production.
```

## 7. Switching Embedding Model (Jina ↔ BGE)

Model selection is **env-driven at container start** (the Settings UI is
read-only — see `v1.3-embedding-migration.md` §3 for the rationale).

```powershell
# ── 1. Edit .env to switch the active model ──────────────────────────────────
# Embedding: jina-v5-small (default) | bge-m3
# Reranker:  jina-v3 (default)        | bge-reranker-base
#
# .env example for switching to BGE:
#   EMBEDDING_MODEL=bge-m3
#   RERANKER_MODEL=bge-reranker-base
#   DOWNLOAD_BGE=1   # MUST be 1 so the BGE weights are present in the image

# ── 2. Rebuild the backend image (if DOWNLOAD_BGE was 0 before, this pulls the
#       BGE weights into the image) ───────────────────────────────────────────
docker compose build backend

# ── 3. Recreate the backend + api-worker containers (model loads at startup) ─
docker compose up -d --force-recreate backend api-worker

# ── 4. Re-ingest documents to regenerate vectors with the new model ──────────
# CRITICAL: existing vectors in Neo4j were made with the PREVIOUS model.
# Cross-model vector similarity is meaningless. Re-ingest every document so
# the persisted vectors match the active embedder.
#
# (The Neo4j vector indexes themselves stay 1024-dim — Jina uses Matryoshka
# truncation to 1024; BGE-M3 is natively 1024. No index re-creation needed.)
#
# Use the Ingest view in the UI (http://localhost:3000) or the REST API.

# ── 5. Verify the new model is loaded ────────────────────────────────────────
docker compose exec backend python -c "from app.services.embedding import get_embedder; e=get_embedder(); e.load(); print(e.model_id)"
# Should print: bge-m3
# Also check the Dashboard's System card in the UI — it reports the active
# embedding + reranker model dynamically.
```

## 8. Troubleshooting

### 8.1 GPU not visible inside the container

```powershell
docker compose exec backend nvidia-smi
# Error: "command not found" or "Failed to initialize NVML"
```

**Fix**:
1. Confirm `nvidia-smi` works on the Windows host.
2. Confirm `docker run --rm --gpus all nvidia/cuda:13.3.0-devel-ubuntu26.04 nvidia-smi` works (this validates the NVIDIA Container Toolkit installation inside WSL2).
3. If step 2 fails: install the NVIDIA Container Toolkit inside WSL2 (see §1 step 4), then restart Docker Desktop.
4. Restart Docker Desktop (right-click the tray icon → Restart).

### 8.2 Model download timeout / failure

```powershell
docker compose build backend
# Error: "huggingface_hub.errors.LocalEntryNotFoundError" or SSL/connection timeout during snapshot_download
```

**Fix** (pick one):
- Increase the HF download timeout via build arg:
  ```powershell
  docker compose build --build-arg HF_HUB_DOWNLOAD_TIMEOUT=300 backend
  ```
- Run `download_models.py` on the host first (you have a fast stable connection), then mount the host's `~/.cache/huggingface` into the build:
  ```powershell
  # On the host (WSL2 or a Python venv):
  pip install "huggingface_hub>=0.24,<0.30"
  DOWNLOAD_BGE=1 python backend/scripts/download_models.py
  # Then mount the cache when building:
  docker compose build --build-arg HF_HOME=$HOME/.cache/huggingface backend
  ```
- Retry — `snapshot_download` with `resume_download=True` resumes from where it left off.

### 8.3 Neo4j auth error / "Neo.ClientError.Security.Unauthorized"

```powershell
docker compose logs neo4j | Select-String "auth"
# Error: "The client is unauthorized due to authentication failure"
```

**Fix**:
1. Confirm `NEO4J_PASSWORD` in `.env` matches what Neo4j was initialised with.
2. On the FIRST run, Neo4j bakes `NEO4J_AUTH=neo4j/P@ssw0rd` into the data volume. Changing `.env` later does NOT update the existing password.
3. To reset: `docker compose down -v` (drops `neo4j_data`), then `docker compose up -d neo4j` — Neo4j re-initialises with the new `NEO4J_AUTH`.

### 8.4 Port conflict (3000 / 8000 / 7474 / 7687 / 6379)

```powershell
docker compose up -d
# Error: "Bind for 0.0.0.0:7474 failed: port is already allocated"
```

**Fix** (pick one):
- Stop the local service that owns the port:
  ```powershell
  # Find the process owning port 7474:
  Get-NetTCPConnection -LocalPort 7474 | Select-Object -First 1 | ForEach-Object { Stop-Process -Id $_.OwningProcess }
  ```
- OR change the host port in `docker/docker-compose.yml`:
  ```yaml
  neo4j:
    ports:
      - "17474:7474"   # host:container
      - "17687:7687"
  ```
  Then access Neo4j Browser at `http://localhost:17474` and update the Bolt URL in any client to `bolt://localhost:17687`.

### 8.5 CRLF errors in scripts (Windows line endings)

```powershell
docker compose exec backend python scripts/init_neo4j.py
# Error: "/usr/bin/env: 'python\r': No such file or directory" or
#        "SyntaxError: unexpected character after line continuation character"
```

**Fix**:
- The repo's `.gitattributes` enforces LF; if you cloned with default Windows git settings, you may have CRLF in working tree.
- Configure git to NOT auto-convert:
  ```powershell
  git config --global core.autocrlf false
  git rm --cached -r .
  git reset --hard
  ```
- OR convert the affected files in place:
  ```powershell
  # If you have WSL2 or git-bash with dos2unix available:
  wsl dos2unix backend/scripts/*.py backend/app/**/*.py
  ```

### 8.6 BuildKit not used (cache mounts silently ignored)

```powershell
docker compose build backend
# Symptom: every build re-downloads multi-GB model weights — no cache reuse.
```

**Fix**:
1. Verify in Docker Desktop → Settings → Build → "BuildKit enabled" is checked.
2. If running Docker Engine (Linux) or an older Docker Desktop, set the env var explicitly:
   ```powershell
   $env:DOCKER_BUILDKIT=1
   docker compose build backend
   ```
3. Verify the cache mount is hit on rebuild:
   ```powershell
   docker buildx build --progress=plain -f docker/Dockerfile.backend ../backend
   # The "RUN --mount=type=cache,target=/root/.cache/huggingface ..." layer
   # should show "CACHED" on the second build.
   ```

## 9. Verification Checklist

- [ ] `nvidia-smi` works in PowerShell on the Windows host.
- [ ] `docker run --rm --gpus all nvidia/cuda:13.3.0-devel-ubuntu26.04 nvidia-smi` works (GPU passthrough via WSL2 + NVIDIA Container Toolkit).
- [ ] `docker compose build` completes for all 5 services without errors.
- [ ] `docker compose run --rm backend python scripts/download_models.py` prints `[download] done (2 model(s))` (or 4 if `DOWNLOAD_BGE=1`).
- [ ] `docker compose run --rm backend python scripts/init_neo4j.py` prints `[init_neo4j] done: N ok, 0 failed`.
- [ ] `docker compose up -d` brings all 5 services to `(healthy)` within ~90s.
- [ ] `curl http://localhost:8000/health` returns `{"status":"ok"}`.
- [ ] `curl http://localhost:3000/api/v1/neo4j/health` returns `{"status":"ok"}` (Next.js proxy → direct Neo4j read).
- [ ] `docker compose exec backend python -c "import torch; print(torch.cuda.is_available())"` prints `True`.
- [ ] `docker compose exec backend python scripts/init_neo4j.py` runs WITHOUT passing `PYTHONPATH` (confirms `PYTHONPATH=/app` is baked into the image).
- [ ] Neo4j Browser at http://localhost:7474 accepts `neo4j` / `P@ssw0rd` and runs `SHOW INDEXES;`.
- [ ] Frontend at http://localhost:3000 renders the Dashboard with the "v1.3 — Jina v5 default + BGE-M3 toggle" stack string in the System card.
