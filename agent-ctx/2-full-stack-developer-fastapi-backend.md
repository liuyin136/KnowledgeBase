- **Decisions made**:
  1. Upload-time documents stored as `:Knowledge` nodes with `embedding_method="Upload"` + `vector=None` (HNSW index skips null-vector nodes) — avoids introducing a `:Document` label that's not in the spec, while keeping upload-time placeholders out of vector search results. `get_document_text` filters to upload-time nodes only so re-ingest doesn't double-count windowed text.
  2. `dashboard_stats.documents` counts DISTINCT source_files (matches v1 sandbox semantics — documents = unique uploaded files, not Knowledge node count which can be >1 per file for LongText multi-window).
  3. `documents.delete` cascades to child KnowledgeChunks via `OPTIONAL MATCH (k)-[:HAS_CHUNK]->(c) DETACH DELETE c, k`.
  4. ProgressTracker has an in-memory fallback (`_InMemoryJobStore`) when Redis is unreachable — so local dev without Redis works (degraded — progress doesn't survive a worker restart). Production uses Redis.
  5. The cross-module Pydantic forward reference (`JobStatusResponse.result: Optional[SearchResponse]`) is resolved via `model_rebuild(_types_namespace={"SearchResponse": SearchResponse})` at the bottom of `schemas/search.py` — explicit namespace avoids lookup ambiguity since the class is defined in search.py but the forward ref lives in ingest.py.
  6. CORS allows all origins by default (`FRONTEND_ORIGIN=*`) for dev; production should set a single origin.
  7. The BGE-M3 model is preloaded at app startup (best-effort — non-fatal if it fails; first request retries the load). This avoids paying the load cost on the first /ingest or /search.
